# 游乡记数据库完整版启动教程

这份教程适合下面这类人：

- 想把项目完整跑起来
- 想让收藏、打卡、社区、搜索历史、后台统计这些功能真的保存到数据库
- 不想只停留在演示模式

这份教程默认按 Windows 电脑来写，并且继续沿用项目里已经自带的 Node 运行环境，所以你依然不需要自己单独安装 Node.js。

## 一、完整版和演示模式有什么区别

### 演示模式

演示模式适合快速看页面。

它的优点是：

- 启动快
- 不需要数据库
- 不需要先安装 PostgreSQL

但它的缺点也很明显：

- 收藏、去过、想去不一定真正保存
- 景点打卡、社区发帖、评论、点赞不完整
- 搜索历史、个性化推荐、后台统计不完整
- 投稿审核和热力图更像展示，不是完整闭环

### 数据库完整版

数据库完整版才是更接近真实可用状态的版本。

接上数据库后，这些功能会完整很多：

- 用户注册与登录
- 收藏、想去、去过
- 景点打卡
- 景点社区发帖、评论、点赞
- 搜索历史
- 个性化推荐
- 用户投稿
- 管理员审核投稿
- 后台统计
- 景点热力图
- 导入数据后真正写入数据库

## 二、你需要提前准备什么

完整版不再要求你在自己电脑上安装 PostgreSQL。数据库放在云上，项目通过连接串去访问。Supabase、Neon、阿里云 RDS，或者其他提供 PostgreSQL 的厂商，都可以。

你需要准备：

1. 这个项目完整文件夹
2. 一个已经创建好的云端 PostgreSQL 数据库
3. 两串连接地址：给网站用的 `DATABASE_URL`，给迁移用的 `DIRECT_URL`
4. 云厂商白名单里已经放行了你这台电脑，以及以后部署网站的服务器的公网 IP

网站本身仍然打开 `http://localhost:3000`。变的是数据存在哪里，不是网页开在哪里。

## 三、创建云数据库

在供应商控制台里新建一个 PostgreSQL 数据库，名字可以用 `youxiangji`。创建时记住用户名和密码。

然后复制两种连接串：

- **池化连接**，给正在运行的网站用。Supabase 一般是端口 `6543`，Neon 的主机名里带 `-pooler`。
- **直连**，给建表、迁移和导入数据用。它不经过 PgBouncer。

如果这家云没有连接池，两串填同一个直连地址即可。阿里云 RDS 默认就是这种情况。

无论哪一家，云上的连接串都要带 `sslmode=require`，除非该实例明确没有开启 SSL。那样就写成 `sslmode=disable`。项目不会把你已经写好的 `sslmode` 再改掉。

密码里如果有 `@`、`#`、`:` 这类符号，要先做 URL 编码再放进连接串。`@` 写成 `%40`。

### Supabase

```env
DATABASE_URL="postgresql://postgres.PROJECT_REF:PASSWORD@aws-0-REGION.pooler.supabase.com:6543/postgres?pgbouncer=true&connection_limit=1&sslmode=require"
DIRECT_URL="postgresql://postgres:PASSWORD@db.PROJECT_REF.supabase.co:5432/postgres?sslmode=require"
```

`PROJECT_REF` 是项目编号。池化用户名是 `postgres.项目编号`，直连用户名是 `postgres`，主机也不一样。

### Neon

```env
DATABASE_URL="postgresql://USER:PASSWORD@ep-EXAMPLE-pooler.REGION.aws.neon.tech/youxiangji?sslmode=require&pgbouncer=true&connection_limit=1"
DIRECT_URL="postgresql://USER:PASSWORD@ep-EXAMPLE.REGION.aws.neon.tech/youxiangji?sslmode=require"
```

Neon 控制台有时会附带 `channel_binding=require`。请删掉这个参数，Prisma 目前使用它会连接失败。项目在运行和执行迁移脚本时也会自动去掉它。

### 阿里云 RDS PostgreSQL

```env
DATABASE_URL="postgresql://USER:PASSWORD@pgm-xxxx.pg.rds.aliyuncs.com:5432/youxiangji?schema=public&sslmode=require"
DIRECT_URL="postgresql://USER:PASSWORD@pgm-xxxx.pg.rds.aliyuncs.com:5432/youxiangji?schema=public&sslmode=require"
```

还需要在 RDS 白名单里加入当前电脑的公网 IP。没有放行时，现象通常是一直超时，而不是提示密码错误。

如果开通了 RDS 数据库代理，`DATABASE_URL` 改成代理地址，并加上 `pgbouncer=true`。`DIRECT_URL` 仍用实例自己的直连地址。

### 其他厂商

只要是 PostgreSQL，就按它控制台给出的格式填。有连接池时，`DATABASE_URL` 用池化地址并加上 `pgbouncer=true`；`DIRECT_URL` 用直连地址。部署到 Vercel 这类无服务器环境时，池化地址再加 `connection_limit=1`。

## 四、配置项目的 `.env`

项目根目录里已经有一个 `.env.example`。

你需要让项目根目录里有一个 `.env` 文件。

如果还没有 `.env`，就复制一份：

```bat
copy .env.example .env
```

或者更简单一点，直接双击：

`2-初始化数据库-完整版.cmd`

如果发现没有 `.env`，它会自动帮你创建，并打开记事本让你编辑。

### `.env` 里最关键的几项

```env
DATABASE_URL="postgresql://USER:PASSWORD@HOST:5432/youxiangji?schema=public&sslmode=require"
DIRECT_URL="postgresql://USER:PASSWORD@HOST:5432/youxiangji?schema=public&sslmode=require"
USE_DEMO_DATA="false"
```

`USE_DEMO_DATA` 必须是 `false`。它只要还是 `true`，网站就只用内置演示数据，云数据库里的内容不会出现在页面上。

请用 npm 脚本执行 Prisma，不要裸跑 `npx prisma`。这些脚本会在 `DIRECT_URL` 留空时，尽量从 `DATABASE_URL` 推导一条直连地址：

```bash
npm run prisma:generate
npm run prisma:push
npm run prisma:deploy
npm run db:check
```

推导不一定对，尤其是 Supabase。迁移失败时，把控制台里的直连串写进 `DIRECT_URL`。

### AI 相关配置要不要改

可以先不改。

即使你没有配置这些内容，数据库完整版也能正常使用大部分功能：

- `ARK_API_KEY`
- `OPENAI_API_KEY`

它们主要影响更高级的 AI 增强能力，不影响数据库本身。

## 五、把表结构和示例数据写入云数据库

当前仓库里还没有 `prisma/migrations` 历史，所以第一次初始化用 `db push`，不需要先装本机数据库。

对新手来说，最简单的方法就是双击：

`2-初始化数据库-完整版.cmd`

它会自动做 3 件事：

1. 生成 Prisma 客户端
2. 用 `DIRECT_URL` 把表结构写入云端 PostgreSQL
3. 导入项目自带的示例数据

想自己在终端里做，按这个顺序：

```bash
npm install
npm run prisma:generate
npm run prisma:push
npm run seed
npm run db:check
```

`db:check` 连得上时，会打印 `连接成功`，以及当前景点和用户数量。种子导入完成后，用户数至少应该有 2。

以后如果要开始保留迁移历史，在能够创建影子库的数据库上执行一次：

```bash
npm run prisma:migrate -- --name init
```

生成 `prisma/migrations` 之后，云上的更新改用：

```bash
npm run prisma:deploy
```

`migrate deploy` 同样走 `DIRECT_URL`，适合已经有迁移文件的生产库。在那之前，继续用 `npm run prisma:push`。

## 六、确认连接的是云数据库

初始化成功只说明表写进去了。再确认网站真的在读这块云数据库：

1. `.env` 里 `USE_DEMO_DATA` 是 `false`
2. 运行 `npm run db:check`，看到 `连接成功`
3. 双击 `3-启动项目-数据库完整版.cmd`，或执行 `npm run dev`
4. 用下面的演示账号登录。登录成功，说明读到的是库里的用户，不是演示模式的临时数据

如果本机以前已经有一份 PostgreSQL 数据，想原样搬到云上，不要再跑种子覆盖它。先把云上的空库准备好，然后在本机执行：

```bat
pg_dump --no-owner --no-acl --dbname="postgresql://postgres:旧密码@localhost:5432/youxiangji" --file=youxiangji.sql
set "DIRECT_URL=这里换成云数据库直连串"
psql "%DIRECT_URL%" -f youxiangji.sql
```

导入前先备份云上已有内容。种子数据和这份旧库不要叠在一起，否则账号和景点可能重复。

## 七、启动数据库完整版

## 十、如果你想重新导入一遍数据库

### 最稳妥的方法

如果你只是想重新初始化一遍，最简单的思路是：

1. 先备份你要留的数据
2. 清空或重建数据库
3. 再重新执行 `2-初始化数据库-完整版.cmd`

### 什么时候需要重新初始化

一般只有下面几种情况才需要：

- 你第一次配置错了数据库
- 你想把示例数据重新恢复成初始状态
- 你改了 Prisma 表结构，想重新推一次

## 十一、最常见的问题

### 1. `prisma:push` 失败

先看这几项：

1. `DATABASE_URL` 和 `DIRECT_URL` 是不是云上的地址，而不是 `localhost`
2. 密码是否写错，特殊字符有没有做 URL 编码
3. 云上的数据库是不是已经创建
4. 白名单或安全组有没有放行当前公网 IP
5. 云数据库是否要求 SSL。要求的话保留 `sslmode=require`
6. 迁移有没有误用了连接池地址。`DIRECT_URL` 必须是直连，不能是带 `pgbouncer=true` 的池化串
7. Neon 连接串里如果还有 `channel_binding=require`，删掉后再试

`npm run db:check` 可以单独测试应用那条连接串。迁移失败而 `db:check` 成功时，优先检查 `DIRECT_URL`。

### 2. 初始化成功了，但登录失败

先确认你是不是用了正确入口：

- 普通用户去 `/login`
- 管理员去 `/admin/login`

再确认账号密码是否正确：

- 普通用户：`demo@youxiangji.local / demo123456`
- 管理员：`admin@youxiangji.local / admin123456`

### 3. 我已经配了数据库，为什么看起来还是像演示模式

重点检查 `.env`：

```env
USE_DEMO_DATA="false"
```

如果这里还是 `true`，那项目还是会走演示模式。

### 4. 为什么我没有看到 AI 联网增强效果

数据库完整版和 AI 完整版不是一回事。

你接上数据库以后，用户数据、互动数据、后台数据会完整。

但如果你还想获得更强的实时 AI 规划能力，你还需要额外配置：

- `ARK_API_KEY`
或
- `OPENAI_API_KEY`

### 5. 为什么第一次不要直接跑 `npm run prisma:migrate`

因为这个项目当前没有现成的 `prisma/migrations` 目录。

第一次接到云数据库，用：

```bash
npm run prisma:push
```

等你确认要开始记录表结构变更，再执行 `npm run prisma:migrate -- --name init`，之后的云上更新用 `npm run prisma:deploy`。

## 十二、最推荐的新手完整流程

如果你只想照着做，按下面这 8 步就行：

1. 在 Supabase、Neon、阿里云 RDS 或其他云厂商创建一个 PostgreSQL 数据库
2. 把运行网站的公网 IP 加进白名单
3. 在 `.env` 里填写 `DATABASE_URL` 和 `DIRECT_URL`，云上地址带上 `sslmode=require`
4. 把 `USE_DEMO_DATA` 改成 `false`
5. 双击 `2-初始化数据库-完整版.cmd`
6. 运行 `npm run db:check`，确认打印 `连接成功`
7. 双击 `3-启动项目-数据库完整版.cmd`
8. 用 `demo@youxiangji.local` 和 `admin@youxiangji.local` 分别测试前台和后台
